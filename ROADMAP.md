# Roadmap: the UkeGeeks song editor and songbook app

Written 2026-11-06. This repo starts as the new home of the Song-a-Matic editor, and the editor is step one toward a desktop (later iPad) songbook app.

## Who it's for

Someone running a ukulele club. They have songsheets (paper, PDFs, text pasted from websites) and want **one tidy songbook** their members can print or read on a tablet. They aren't looking for a guitar tab editor. The existing song editors are mostly for guitar and mostly too complicated; simple and uke-first is the opening.

## How the pieces stack

```
Songbook (self-hosted) · ukegeeks.org · the desktop app
        └── Song editor (this repo): menus, dialogs, Chord Builder, fullscreen editing
              ├── Song Formatter: reads ChordPro, draws the songsheet and SVG chord diagrams
              └── ACE ChordPro Extension: highlighting and autocomplete, fullscreen only
```

Each layer only knows the one below it.

- A read-only song page loads **Song Formatter** alone. The editor is the extra layer for pages where you change the song.
- The editor **doesn't bundle** Song Formatter or Ace. It needs them on the page (peer dependencies), so there's never a second copy, and each piece releases on its own schedule. Ace still loads only when someone clicks Fullscreen.
- The page or app that hosts the editor decides **where songs live and what "save" means**.

## Phase 1: pull the editor out of the Songbook

Goal: the editor lives here as its own npm package, and the Songbook uses it with **no visible change**.

### What moves here, from `~/Code/UkeGeeks`

- **JavaScript:** `src/js/editor/*.js` (about 5,100 lines) plus `src/js/libs/lazyload.js`. The build order matters; it's listed in the Songbook's `scripts/build.js` (the `BUNDLES` list), with the namespace first.
- **Styles:** `src/less/ugsEditorPlus_merged.less`, `src/less/editor/*.less` and `src/less/mixins/`. Output today: `css/ugsEditorPlus.merged.css` and `.min.css`. Print styles: `css/ugsEditorPlus.print.css` (hand-written, not generated). `css/ugsEditorPlus.typeahead.css` belongs to the song list page and stays.
- **Images:** `img/editor/*.png` and `busy.gif` (sprite, buttons, Chord Builder hand cursor, wood texture).
- **The page markup**: toolbar, Edit Song dialog, Appearance/Transpose/Options menus, Help, Reformat dialog, Chord Builder. Today it's copied by hand into at least four places:
  - Songbook Node templates: `server/views.js` (`songEditable()`)
  - Songbook PHP templates: `ugsphp/views/song-editable.php`
  - ukegeeks.org `src/songeditor/index.html`
  - ukegeeks.org `src/songbook/*.html` (generated by the Songbook's static build)

  The package should generate it, so a host page only needs an empty container.

### What stays in the Songbook

- `ugsEditorPlus.typeahead.js`: quick search on the song list page.
- `ugsEditorPlus.newSong.js`: the "new song" dialog on the song list page, which posts to the server.
- The server, login and song storage.

### What becomes pluggable

- **Saving.** `ugsEditorPlus.updateSong.js` posts to `/ajaxupdatesong` today. Turn it into a host-supplied `save(song)` callback (returning a promise): the Songbook posts to its server, the app writes a file, and ukegeeks.org passes nothing, so there's no Save button.
- **Settings.** The `ugsEditorPlus.options` defaults, passed in by the host as now (`songAmatic.init(options)`).

### API sketch (decide the details in the session)

```js
ugsEditorPlus.songAmatic.mount(containerElement, {
  song: chordProText,         // the song to open
  save: async (text) => {},   // optional; no Save button without it
  aceUrl: '/js/ace/',         // where ace-chordpro.min.js lives
  ...options,                 // today's ugsEditorPlus.options
});
```

Keep the existing global (`window.ugsEditorPlus`) and `init()` working, so existing pages don't break.

### Ground rules for phase 1

- **Move, don't rewrite.** Same code and behavior in a new home. Modernizing (modules, TypeScript, dropping LESS) is a later phase, once the editor stands on its own.
- New code uses 2-space indentation with no tabs. The moved legacy files use tabs: match the file.
- Generated files (merged and min JS/CSS) come from a build script; never hand-edit them.
- Check the editor side by side with the Songbook's current `master` on the 16 sample songs in `~/Code/UkeGeeks/cpm/`: same chords, diagrams, transpose, tunings (GCEA, DGBE, ADF#B), mini-diagrams, Chord Builder, fullscreen and print.

### Done means

1. This repo builds the editor bundle, CSS and images, with tests, and is ready to publish to npm (the owner publishes).
2. A branch in `~/Code/UkeGeeks` that installs the package, copies its files at build time like the other two packages (`scripts/build.js`, `VENDORED`), deletes the moved sources, and passes `npm test` and the side-by-side check.
3. ukegeeks.org follows later, by syncing the Songbook's build as it does now.

## Phase 2: Mac prototype

A **Tauri 2** app. Tauri wraps the existing web code in a small native app for Mac and Windows, and the same project can later build for iPad; Electron can't do iPad.

- Open or create a "songbook" folder. Each song is a plain-text ChordPro file (the same format as the Songbook's `cpm/` folder), so nothing is locked in.
- List the songs; open one in the editor; Save writes the file.
- **No server.** The Songbook's Node server is replaced by direct file access through Tauri. Reuse its song parsing (`server/lib/songs.js`: title, artist, sorting).

Done means: it runs on the owner's Mac from a dev build, opens `~/Code/UkeGeeks/cpm/`, and edits and saves a song.

## Phase 3: add a song from a songsheet

Paste a songsheet; the existing plain-text-to-ChordPro converter (`ugsEditorPlus.reformat.js` and `autoReformat.js`) turns it into ChordPro, and the editor opens it.

## Phase 4: make the songbook

The feature uke clubs want: pick songs, order them, and export **one PDF** with a cover, table of contents, page numbers and consistent formatting. Members get a PDF they can print or open on an iPad today, before any iPad app exists.

## Phase 5: ship for Mac and Windows

App icon (the Maestro Saurus favicon set is in `~/Sites/ukegeeks.org/resources/favicon/package/claude/`), installers, code signing, remembering the last songbook, and an About page linking to ukegeeks.org.

## Phase 6: iPad

The same Tauri project built for iPadOS. Needs full Xcode; today the machine has only the Command Line Tools. Rust 1.99 and Node 24 are installed.

## Working conventions

- Work on a branch; never commit to `main`/`master`. Commit each finished chunk; one PR per piece of work.
- Markdown: a blank line between paragraphs.
- No PHP on this machine. To lint PHP, use `@php-wasm/cli` in a scratch folder.
- The owner pushes, publishes to npm and deploys; prepare the commands for them.
